# 等值面提取（Isosurface Extraction）

本目录实现了三种从标量场 `f(x, y, z)` 中提取等值面 `f = isov` 的算法，主要用于分子体系的正、负等值面绘制
（例如分子轨道 / 电子密度的 `±isov` 等值面）。

| 文件 | 算法 | 一句话说明 |
| --- | --- | --- |
| `mod.rs` | 公共设施 | 网格约定、区域采样、顶点焊接、平滑、投影 |
| `mc.rs` | Marching Cubes | 经典三角表法，速度最快，但存在歧义可能留孔 |
| `mt.rs` | Marching Tetrahedra | 立方体切成 6 个四面体，无歧义、天然水密 |
| `sn.rs` | Surface Nets | 每个立方体只出一个顶点，三角形数最少、天然水密 |

三者**接口完全一致**，可以互相替换。

---

## 1. 公共约定

### 1.1 统一的函数签名

底层提取函数都遵循同一个签名：

```rust
fn extract(
    shape: &[usize; 3],       // 网格尺寸 [nx, ny, nz]
    grids: &Vec<[f64; 3]>,    // 每个网格点的世界坐标
    values: &Vec<f64>,        // 每个网格点上的标量值
    isov: f64,                // 等值面的值
) -> (Vec<[f64; 3]>, Vec<isize>);
```

返回值是 `(顶点表, 类型表)`：

- 顶点表是**三角形汤**（triangle soup）：每 3 个点构成一个三角形，没有索引。
  需要带索引的网格时，可用 `merge_verts` 焊接成 `(verts, faces)`。
- 类型表与顶点表一一对应，`+1` 表示该顶点属于 `f = +isov` 层，`-1` 表示属于 `f = -isov` 层。
  这样一次调用就能同时拿到正、负两层面片，后续平滑/投影时靠它区分目标值。

三个底层函数 `march_cube_v1`、`march_tetra_v1`、`surface_nets_v1` 都同时提取 `+isov` 与 `-isov`
两层；负层结果会做一次 `reverse()` 翻转绕向，保证内外面朝向一致。

### 1.2 网格与编号约定

- 扁平下标由 `grid_index` 给出：`(i * ny + j) * nz + k`，即 `i` 最慢、`k` 最快。
- 立方体 8 个角点的顺序由 `DIDX` 定义：

  ```
  0:(0,0,0)  1:(1,0,0)  2:(1,1,0)  3:(0,1,0)
  4:(0,0,1)  5:(1,0,1)  6:(1,1,1)  7:(0,1,1)
  ```

  即「先按 z=0 平面逆时针走一圈，再按 z=1 平面逆时针走一圈」。
- 12 条棱由 `EDGES` 定义，棱号 `0..11` 与 `mc.rs` 中的 `MARCH` 三角表严格对应：

  ```
  0:(0,1) 1:(1,2) 2:(2,3) 3:(0,3)     // z=0 平面
  4:(1,5) 5:(2,6) 6:(3,7) 7:(0,4)     // 沿 z 方向的竖棱
  8:(4,5) 9:(5,6) 10:(6,7) 11:(7,4)   // z=1 平面
  ```

- `NaN` 被用作「不参与计算」的掩码（见 `extract_region` 的距离裁剪）。所有算法在遇到立方体角点含
  `NaN` 时都会直接跳过该立方体，因此不会产生错误的面片。

### 1.3 立方体区域 `Cube`

`Cube` 表示一个轴对齐的长方体，提供：

- `grids_v1(count)`：按期望的总格点数反推步长，在内部均匀布点；
- `grids_v2(step)`：按给定步长布点（端点上额外 `+1`，保证覆盖整个区间）；
- `calc_step(count)` / `volum()` 等辅助方法。

## 2. 三种算法

### 2.1 Marching Cubes（`mc.rs`）

最经典的做法：对每个立方体，用 8 个角点与 `isov` 的大小关系组成一个 8 位 key（`0..255`），
查 `MARCH` 表得到该 case 需要连接哪些棱，再在对应棱上做线性插值求交点。

```text
key = Σ (vals[n] > isov ? 1 << (7 - n) : 0)     // n = 0..7
```

关键实现点：

- `MARCH: [[i8; 24]; 256]` 内联在文件中，每个 case 最多 8 个三角形；不足的槽位用 `-1` 填充，
  读到 `-1` 即表示该 case 结束。
- `get_boxverts(key, xyzs, vals, isov)` 负责查表并把棱上的插值点按每 3 个一组压入结果。
- `march_cube_v1` 会先通过 `grids2voxel` 把扁平数组整理成 `Array4<f64>`（每点存 `x, y, z, value`），
  再扫描所有立方体。这会额外分配一份与网格等大的内存。
- 判定条件是严格不等式 `vmin < isov && isov < vmax`，因此等值面恰好穿过角点的情况会被跳过。

**优点**：查表实现简单、速度快、三角形数量少。
**缺点**：经典 MC 在部分 case（所谓「歧义面」）上，同一个立方体存在多种合法连法，相邻立方体若选择不一致
就会在共享面上留下孔洞或内部裂缝。本实现使用的表没有做歧义消解。

### 2.2 Marching Tetrahedra（`mt.rs`）

为了解决 MC 的歧义问题，把每个立方体按 **Kuhn 分解** 切成 6 个四面体，全部共用主对角线 `0-6`：

```
[0,1,2,6]  [0,2,3,6]  [0,3,7,6]
[0,7,4,6]  [0,4,5,6]  [0,5,1,6]
```

每个四面体只有 4 个顶点，与等值面相交时只可能出现两种拓扑：

| 内部顶点数 | 交线形态 | 处理 |
| --- | --- | --- |
| 1 或 3 | 三角形 | 3 条交叉棱上的点连成 1 个三角形 |
| 2 | 四边形 | 4 条交叉棱上的点连成 1 个四边形，再拆成 2 个三角形 |

这两种情况都**没有歧义**，因此 `mt` 的输出天然水密（watertight）。

实现细节：

- `TET_EDGES` 给出四面体的 6 条棱（用四面体局部顶点号 `0..3`）。
- `tet_triangles` 先计算「内部顶点质心」与「外部顶点质心」，以两者之差作为朝外方向 `dir`；
  再对齐每个三角形的法线（`dot(n, dir) < 0` 时交换后两个顶点），保证同层绕向统一。
- 4 条交叉棱按「共享一个四面体顶点」的关系排成环，避免四边形顶点乱序导致自交。
- 立方体级别的粗筛先把 8 个角点的 `NaN` 与 `vmin/vmax` 判掉，再逐个四面体处理。

**优点**：无歧义、水密、实现比 MC 查表更简洁。
**缺点**：三角形数量明显多于 MC；Kuhn 分解方向固定，原始输出表面会显得皱。

因此 `march_tetra_v2` 在调用 `extract_region` 之后额外做了
`smooth_isosurface`（焊接 + 6 次 Taubin 平滑 + 重新投影回真实等值面），代价是多几次 `func` 求值。

### 2.3 Surface Nets（`sn.rs`）

Surface Nets 属于「对偶」方法（Dual Contouring 的简化版），思路与 MC/MT 完全不同：

1. **每个与等值面相交的立方体只生成一个顶点**，位置取「12 条棱上所有交点位置的平均」。
   顶点天然由立方体共享，不需要额外焊接。
2. **每条符号发生变化的网格棱生成一个四边形**（拆成 2 个三角形），连接这条棱周围一圈的 4 个立方体顶点。

代码分两遍扫描：

- 第一遍：为每个相交立方体计算顶点，并记到 `cell_v`（`usize::MAX` 表示该立方体没有顶点）。
- 第二遍：分别沿 x / y / z 三个方向枚举网格棱，检查 `(v0 > isov) != (v1 > isov)`，
  然后按方向取周围 4 个立方体的顶点索引组成四边形。每圈顶点的顺序由 `s0 > isov` 决定，
  保证法线统一朝「值减小」的一侧。
- `emit` 会把四边形拆成 `(a, b, c)` 与 `(a, c, d)` 两个三角形；若 4 个顶点中有任一为
  `usize::MAX`（相邻立方体因 `NaN` 被跳过），该四边形直接丢弃，不会产生越界或退化面。

**优点**：三角形数量比 MC / MT 都少，结果水密、流形，且顶点天然共享。
**缺点**：顶点落在立方体内部而非真实等值面上（只有平均意义下接近），因此形状略「方」；
不做后处理时会有明显的阶梯感，通常需要配合 `snap_to_isosurface` 使用。

> 注意：`surface_nets_v1` 对外仍然返回三角形汤，为了与其他两个算法保持同样的接口。
> 内部第一遍算出的共享顶点在第二遍展开时被复用；若要得到带索引的网格，可以对结果调用 `merge_verts`。
> 另外第二遍扫描的边界从 `1` 开始（`j in 1..cy` 等），即最外一层网格棱不生成面，
> 这一层本来也无法凑齐 4 个相邻立方体。

## 3. 公共流程：`extract_region`

`extract_region(func, cube, isov, step, xyzs, limit, extract)` 是连接「标量场函数」与「具体算法」的桥梁，
三个 `*_v2` 接口都走这条路径。它实现的是一套**由粗到细的两级采样**，避免对整个空间做全分辨率采样：

1. **粗网格面采样**：把大区域按 1 Å 切成小立方体，再对每个小立方体 6 个面分别以 `step` 间隔布点，
   用 `rayon` 并行求值，存进 `HashMap<(axis, ix, iy, iz), Vec<f64>>`。
   相邻立方体共享同一个面，所以同一个面只会被采样一次。
2. **筛选相交立方体**：对小立方体，检查它 6 个面的采样值是否可能跨过 `+isov` 或 `-isov`；
   不可能跨过的整块跳过。这一步能过滤掉分子周围绝大部分空白区域。
3. **精细提取**：对通过筛选的小立方体用 `cube.grids_v2(step)` 重新按真实步长布点求值，
   再调用传入的 `extract` 得到该块的三角形。
4. **距离裁剪**：可选参数 `limit` 配合 `xyzs`（如原子坐标）使用——离所有参考点都超过 `limit` 的网格点
   直接填 `NaN`，从而少算一些 `func`。这也是各算法必须处理 `NaN` 的原因。

参数 `extract` 是一个函数指针/闭包，这样同一套采样与筛选逻辑可以服务三种算法：

```rust
super::extract_region(&func, cube, isov, step, xyzs, limit, march_cube_v1)
```

## 4. 后处理

### 4.1 `merge_verts` —— 顶点焊接

把三角形汤里位置相同（距离 `< 1e-4`）的顶点合并为一个，输出 `(verts, faces)`。
同时丢弃因焊接而退化的三角形（有两个索引相同）。注意它是 `O(n²)` 的双重循环，
只适合中小规模的网格，大规模数据请用 `smooth_isosurface` 内部的哈希焊接。

### 4.2 `snap_to_isosurface` —— 投影回等值面

`snap_point` 用牛顿迭代把顶点拉回 `f(p) = target`：

```
d = f(p) - target
g = ∇f(p)          // 中心差分，步长 h
p ← p - (d / |g|²) · g
```

迭代 2 次，遇到非有限值或梯度过小（`< 1e-12`）时提前返回。它能消除交点「卡在网格棱上」造成的锯齿，
常用于 Surface Nets 输出去阶梯化。

### 4.3 `smooth_isosurface` —— 焊接 + Taubin 平滑 + 重新投影

`march_tetra_v2` 使用的完整后处理流程：

1. **哈希焊接**：按坐标 `×1e5` 取整作为 key 建 `HashMap`，把三角形汤变成带索引的共享顶点，
   同时保留每个顶点的 `type`。
2. **建立邻接表**：从三角形边构造每个顶点的邻居列表。
3. **Taubin 平滑**：交替执行 `λ = 0.5`（收缩）与 `μ = -0.53`（膨胀）两步拉普拉斯平滑，
   重复 `iterations` 次。λ/μ 交替能抵消普通拉普拉斯平滑带来的整体收缩。
4. **重新投影**：用 `snap_point` 把平滑后的顶点沿梯度拉回各自的 `±isov` 等值面，
   使平滑只改变分布、不破坏形状。
5. 按原索引顺序重新展开成三角形汤。

代价是重建了拓扑并多次调用 `func`（梯度是中心差分，每步 6 次求值）。

### 4.4 其余辅助函数

- `value_merge`：把正、负两层的 `(verts, faces)` 合并成一套，负层索引整体偏移 `pverts_count`，
  并生成 `types`。适用于「先分别带索引地提取、再合并」的流程。
- `flatten`：把 `Vec<[f64; 3]>` 与 `Vec<[usize; 3]>` 展平成连续的 `Vec<f64>` / `Vec<usize>`，
  便于传给渲染或文件写出层。
- `grids2voxel` / `voxel2cubes` / `get_around_v2`：基于 `Array4` 体素容器的辅助逻辑。
  其中 `grids2voxel` 仍被 `march_cube_v1` 使用（因此 MC 会多一份内存拷贝）；
  `voxel2cubes` 与 `get_around_v2` 目前没有被主流程调用，保留作为工具函数。

## 5. 对比

| 维度 | Marching Cubes | Marching Tetrahedra | Surface Nets |
| --- | --- | --- | --- |
| 每立方体三角形数 | 少 | 多（常见 1.5~2×） | 最少 |
| 拓扑歧义 | 有（未消解） | 无 | 无 |
| 水密性 | 可能留孔 | 水密 | 水密 |
| 顶点位置 | 棱上插值 | 棱上插值 | 立方体内平均 |
| 表面光滑度 | 好 | 原始偏皱，需平滑 | 偏「方」，需投影 |
| 是否需要后处理 | 否 | 建议（`v2` 已内置） | 建议 |
| 实现复杂度 | 低（查表） | 中 | 中 |
| 入口函数 | `march_cube_v1/v2` | `march_tetra_v1/v2` | `surface_nets_v1` |

选型建议：

- 只求快、能接受偶发小孔 → **MC**；
- 要求拓扑正确、水密，且能承担更多三角形与几次平滑 → **MT**；
- 想要面数最少、网格干净，且愿意做投影去阶梯 → **SN**。

## 6. 用法

```rust
use rswfn::march::{Cube, mc, mt, sn};

// 标量场：例如某个分子轨道的波函数值
let func = |p: &[f64; 3]| { /* ... */ };

let cube = Cube::new([-5.0, -5.0, -5.0], [5.0, 5.0, 5.0]);
let isov = 0.02;   // 同时提取 f = +0.02 与 f = -0.02 两层
let step = 0.1;    // 采样步长（Å）

// 方式一：直接拿三角形汤（每 3 个点一个三角形）
let (verts, types) = mc::march_cube_v2(&func, cube, isov, step, None, None);

// 方式二：MT + 自动平滑
let (verts, types) = mt::march_tetra_v2(&func, cube, isov, step, None, None);

// 方式三：Surface Nets，再手动投影去阶梯
let (mut verts, types) =
    rswfn::march::extract_region(&func, cube, isov, step, None, None, sn::surface_nets_v1);
rswfn::march::snap_to_isosurface(&mut verts, &types, isov, &func, step * 0.5);

// 需要带索引的网格时焊接一下
let (v, faces) = rswfn::march::merge_verts(&verts);
```

`xyzs` 与 `limit` 参数用于按距离裁剪：传入原子坐标列表和半径上限后，
离所有原子都超过上限的网格点会被标记为 `NaN` 并跳过，从而减少 `func` 的调用次数。
不需要裁剪时二者都传 `None` 即可。

## 7. 已知限制

- **MC 的歧义未消解**：`MARCH` 是经典查表，对「歧义面」case 没有做一致性选择，理论上可能出现孔洞。
  对水密性有要求时请用 MT 或 SN。
- **MC 的边界判定用严格不等式**：`vmin < isov && isov < vmax`，等值面恰好经过网格点时该立方体被跳过；
  MT / SN 用的是 `vmin > isov || vmax < isov` 才跳过，边界行为略有差异。
- **`march_cube_v1` 有额外内存开销**：`grids2voxel` 会构造一份 `Array4<f64>`（4 个 f64 / 点）。
- **`merge_verts` 是 `O(n²)`**：只适合小网格；大网格请用 `smooth_isosurface` 的哈希焊接。
- **`smooth_isosurface` 的焊接精度**是坐标 `×1e5` 取整，坐标量级很大或很小时需要留意。
- **SN 第二遍扫描跳过最外层网格棱**，因此边界处的面片会缺失一个单元宽度。
- **`extract_region` 的粗筛基于 1 Å 分块**，若 `step` 远小于或远大于 1 Å，
  筛选粒度与实际采样粒度不匹配，可能有性能或漏检方面的副作用。
- `extract_region` 在小立方体不在面表中时会 `log::error!` 并直接 `std::process::exit(1)`，
  属强耦合的防御式处理，宿主程序需注意。
